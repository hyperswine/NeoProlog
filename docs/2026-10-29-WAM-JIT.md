# Core WAM instruction stream and native JIT - 2026-10-29 (design)

A plan for the next engine phase: make the Core's representation cheaper to
touch, replace its tree-walking plans with an orthodox WAM instruction
stream, and add a Sol-style native JIT tier that compiles deterministic
predicates to machine code at load time. The pattern for the JIT tier is
the Sol profile in the sibling `fprisc` checkout
(`compiler/Sol/JitCore.hs`, `compiler/Sol/HandJIT.hs`,
`compiler/Sol/AsmA64.hs`, `compiler/Sol/AsmX64.hs`, `compiler/cbits`):
a small admissible fragment, per-callsite specialization, hand-rolled
assemblers with no LLVM, executable memory through a tiny C shim, budget
accounting, and refuse-and-fallback as the permanent safety valve.

`fprisc` is not part of this repository and is MIT licensed, while Infera is
GPL-3.0-only. Everything lifted from it is vendored into this repository
under `src/Infera/Core/Jit/` and `cbits/`, retaining the MIT copyright
notice; links to it are written as `fprisc:compiler/...` paths rather than
relative links, which would be dead for any other reader and on the
published documentation site. See [Provenance](#provenance-and-vendoring).

Where this page disagrees with the earlier Core pages, this page wins; it
supersedes the "remaining work" list at the end of
[PER-CALL-COSTS](2026-10-20-PER-CALL-COSTS.md) with a concrete ordering.

**Status.** Step 1 landed on 2026-10-29 and differs from the design below in
one respect worth carrying forward: it pinned the blocks and cached their base
addresses in register slots, but kept growth-by-copy instead of reserving the
address space once, so `rCAP` still means "current block size" and the
invariant it leans on is the written-down one - no base pointer survives an
allocation that can grow its block. See
[PINNED-STORE](2026-10-29-PINNED-STORE.md). Everything else here is still
ahead, except that the load-time half of Step 2 has since been implemented
along the lines the "Load-time compilation" section was corrected to
describe.

## Starting point

The Core is the public engine ([ENGINE-DIAGNOSIS](2026-10-17-ENGINE-DIAGNOSIS.md));
the legacy `Machine/*` stays as fallback oracle and is not modified by this
plan. The measured gap, on the current baseline
([PER-CALL-COSTS](2026-10-20-PER-CALL-COSTS.md), with the external ratios
from [ENGINE-EXTERNAL](2026-10-18-ENGINE-EXTERNAL.md)):

| Workload | Core ms | ÷ SWI | ÷ Scryer |
| --- | ---: | ---: | ---: |
| Reverse, 100 x 30 | 8.30 | ~9.3x | ~2.5x |
| Loop, 90,000 | 8.71 | ~4.7x | ~1.0x |
| Fibonacci 25 | 37.76 | ~3.5x | ~1.3x |
| First 8-queens | 8.31 | ~3.4x | ~1.5x |

Reverse is the worst case and the target of this plan; the counting loop is
already the best relative result. The causes are known: generic
tree-walking interpretation of `[Goal]`/`[Pattern]`/`Expr` values through
`step'`/`buildArg`/`unifyPattern`
([Run.hs](../src/Infera/Core/Run.hs)), per-query plan compilation, generic
head matching and construction, and per-cell-access overheads in the store.

The Core representation itself is already WAM-like and stays: tagged `Int`
words with low-three-bit tags (`REF/STR/FUN/INT/ATM/BOX/CHR`,
[Store.hs](../src/Infera/Core/Store.hs)), one growable unboxed heap, one
binding write per binding, trail-if-`addr < HB` trailing, unboxed choice
stack with per-call marks, mark-compact collection at call boundaries, and
continuations as GHC values. The last of these is deliberate: an experiment
with unboxed WAM environment frames was 5-14% slower than nursery-allocated
continuations in GHC
([PER-CALL-COSTS](2026-10-20-PER-CALL-COSTS.md) "What did not work"), and
this plan does not revisit it.

## Step 0 - two cheap experiments that can reorder this plan

Both are days, not weeks, and each can change the ordering below. They run
before Step 1 lands.

1. **Admissibility coverage.** Instrument the Core with a counter per
   benchmark that classifies each dynamic call against the Step 3
   admissibility predicate as it will be written: tail-loop det fragment,
   then that plus structure arguments, then that plus semidet comparison
   bodies. Report the fraction of dynamic inferences each fragment would
   cover on reverse, loop, fibonacci and queens. If the tail-loop fragment
   covers a few percent of reverse and queens, Step 3's expected value sits
   well below Step 2's and the sequencing changes. This is the
   highest-information cheap measurement available before any of this work.
2. **Executable memory on macOS arm64.** `mmap(MAP_JIT)` plus
   `pthread_jit_write_protect_np` plus one `ret 42` routine, called through
   a dynamic-import `ccall` from a `-threaded` GHC program. If that does not
   work on the development host and on the `macos-26` CI leg, the tier is
   x86-64/Linux-only and Step 2 must not be scoped around it. See the
   corrected risk in [Risks](#risks): the shim this plan intended to reuse
   does not do this today.

## Step 1 - the store: pinned, stable, one indirection less

Three changes to [Store.hs](../src/Infera/Core/Store.hs) that belong
together: the reserve-once block is what makes the base pointer immutable,
and the immutable base is what removes the indirection.

1. **Reserve once, never move.** Because the collector is mark-compact at
   call boundaries and native spans are leaf-per-call, the simplest way to
   guarantee a stable base is to reserve a large block up front (256 MB to
   1 GB of address space through `mallocBytes`, lazily committed by the
   kernel, so resident set stays proportional to touched cells) and let
   `rCAP` be the reservation. The current initial block is already 1048576
   cells (8 MB), and `growCells` quadruples it and copies the live prefix -
   which can happen in the middle of a call, from any `pushCell`,
   `reserveCells` or `allocFrame`. Reserving deletes growth-by-copy and with
   it every stale-base hazard, for the interpreter and for Step 3 alike.
2. **Pinned storage, because native code needs an address that cannot
   move.** An `IOUArray` is backed by an unpinned `MutableByteArray#`, which
   the GHC collector may relocate, so no stable base address can be handed
   to native code today. Move the heap, trail and bound log to pinned blocks
   outside the GHC heap (`mallocBytes` wrapped in a `ForeignPtr` with
   `finalizerFree`, or `mallocPlainForeignPtrBytes` for the smaller arrays);
   `base` provides both, so no new dependency is added. Step 3 reads the
   base at entry to each native call. Pinned storage also makes a native
   span GC-safe by construction: it touches no GHC heap at all.
3. **An immutable base field, then unboxed locals.** Today
   `cells :: IORef (IOUArray Int Int)`, so a cell touch is a MutVar load, an
   `IOUArray` box load, and the indexed access - three dependent loads on
   every path, including `deref` chains and unification. Moving the pointer
   into a register slot does **not** fix this: `regs` is itself an
   `IOUArray`, so reading `rCELLS` costs a box load plus an indexed load,
   which is what the `IORef` cost. What removes the loads is (a) with the
   block reserved once, holding its address in an immutable `Store` field
   (`cellsBase :: !(Ptr Int)`), so the load is one field of an already-live
   box and GHC hoists it out of loops, and (b) threading that address into
   hot functions as an unboxed local, re-reading it nowhere. Every cell
   touch then becomes one indexed load or store through `intPtrToPtr`. The
   trail and bound-log bases get the same treatment. The boxed table does
   not: `boxes :: IOArray Int Boxed` holds Haskell values and cannot live in
   raw pinned memory.

   If the reservation is not taken and growth-by-copy stays, the base cannot
   be an immutable field, and the invariant it depends on must be written
   down and checked: **no base pointer is cached across an allocation.** It
   is currently implicit in the `arr <- readIORef (cells s)` pattern in
   `deref`, `structureWord`, `allocFrame`, `unwindTrail`, `saveArgs` and
   `loadArgs`. A debug build that bumps a generation counter on growth and
   asserts cached generations match would make it explicit - and in that
   variant the win in item 3 largely disappears, which is the argument for
   item 1.

What does not change: the tag layout, the `FUN` word packing (arity in the
low 19 bits, ground memo at bit 22, functor id above bit 20), the
61-bit immediate range, `markerWord` activation blocks, interning
(compile-time, with runtime interning only for builtin constants), the
collector's invariants, and the six parallel choice-stack arrays (cold path
only). The register file's sixteen slots (`rH`-`rVAL` 0-8, `rGCLIM` 9,
`rCLP` 10, `rBOUND` 11, `rIDENT` 12, `rGCCOUNT`/`rGCLIVE`/`rGCRECLAIM`
13-15) stay as they are: the new base addresses are immutable `Store`
fields, not registers, so nothing has to be renumbered. `rCAP` changes
meaning from "current block size" to "reservation size". The same
unboxed-local threading that helps `cellsBase` applies to the hot counters
`rH`, `rTR` and `rHB`, which today each cost an `IOUArray` box load plus an
indexed load on every `pushCell`, `reserveCells`, `bind` and `trailIf`.

One new edge needs defined behaviour: **exhausting the reservation**. With
`initialCollectLimit` at 262144 cells and collection at call boundaries, a
1 GB reservation is roughly four thousand times the working set the collector
allows, so this is an error path rather than a performance path - report it
as a store limit, in the same shape as the resolution-depth cap. If a real
workload ever reaches it, the alternative is growth-by-copy performed only
at a call boundary, where no native span is active and the new base is
published before any further access; that variant gives up item 3's
immutable field and its hoisting.

Acceptance: the full suite passes unchanged; `core-engine parity` passes
**with `--gc-limit 1`**, which forces collection at nearly every call and
therefore exercises the compaction and address-relocation paths this step
touches; a targeted test reaches the reservation limit from a deliberately
tiny reservation (`runCoreWith` already takes an explicit collection
threshold; the store needs the same lever for capacity) and checks the
reported limit; per-call cost on [core-major](../bench/core-major.hs) is
flat or better; ticky shows `deref`/`unify` cost centres flat or lower and
GHC allocation per call on the four standard workloads flat or lower.

Set the expectation before measuring: this removes two dependent loads per
cell touch on the paths where the base is hoisted, and store operations are
a minority of reverse's ~145 ns per inference. A few percent is the
realistic outcome, not the 15-22% the last three commits bought. That is
still worth having, it is a prerequisite for Step 3, and it is the
lowest-risk step in the plan.

**As landed** ([PINNED-STORE](2026-10-29-PINNED-STORE.md)): items 2 and 3
were taken and item 1 was not. The blocks are `mallocForeignPtrBytes` and the
bases live in register slots `rCELLS`/`rTRAILB`/`rBOUNDP` with their
capacities beside them, so a cell touch is one register read and one memory
operation; growth still copies into a larger block. That made the invariant
"no base pointer is cached across an allocation that can grow its block"
load-bearing rather than eliminable, which is why it is now written down in
the module header of [Store.hs](../src/Infera/Core/Store.hs) and why the
measurement came in at 22-34% rather than the few percent predicted here.


## Step 2 - the instruction stream

Replace the per-clause `[Goal]`/`[Pattern]` plan trees produced by
[Compile.hs](../src/Infera/Core/Compile.hs) with a flat instruction array
per predicate, unboxed words, one opcode word followed by its operand words.
This is the classic WAM shape. It also makes Step 3 tractable: the JIT
lowers instructions to machine code instead of tree-walking Haskell.

**The scope is the control state, not the encoding.** Writing the opcode
table is the small part. `Cont` has eight constructors and `Alt` twelve, and
they carry `[Goal]`, `Pattern` and `Pred` values throughout: `CGoals [Goal]
!Int !Int !Int Cont`, `CExitIf !Int [Goal] ...`, `CExitFindAll ... Pattern
...`, `CExitTable (IORef Fix)`, `AltClauses !Pred !(UArray Int Int) !Int
!Int Cont`, `AltGoals [Goal] ...`, `AltRetract`, `AltOptimize`. Each becomes
an offset plus a frame base, or a boxed side entry. That touches the retry
path, cut and guard heights, tabled fixpoints and the CLP rollback marks
across a 3,004-line driver with a large generated-parity suite. Two
decisions keep most of that risk out:

* **A hybrid stream.** The flat encoding covers the hot first-order subset
  only: head matching and unification, argument construction, arithmetic,
  `CALL`/`EXECUTE`, cut and if-then-else commit, and index dispatch.
  Everything exotic stays a boxed `Goal` reachable through one instruction,
  `ESCAPED n`, indexing a per-predicate escape table. `GFindAll`,
  `GMinimize`, `GTabled`, `GAssert`/`GRetract`, `GLeaf`, `GPhrase`,
  `GCallDyn` and `GUnsupported` then need no re-expression, their `Alt` and
  `Cont` constructors stay exactly as they are, and the JIT declines any
  span containing `ESCAPED`.
* **No `TRY`/`RETRY`/`TRUST` alongside the existing candidate iteration.**
  Clause selection already produces shared `Candidates` (a `UArray Int Int`
  of ordinals, allocation-free since `e47bc65`,
  [CLAUSE-SELECTION](2026-10-19-CLAUSE-SELECTION.md)) and the choice point
  walks it through `markNext`. WAM try/retry/trust chains would be a second
  mechanism for the same job and would force the choice point to carry a
  code offset. Keep ordinals, add a per-clause entry-offset `UArray`, and
  let `SWITCH_TAG` remain a filter that yields a candidate set. The JIT can
  still emit a native jump table over the deterministic fragment.

Proposed instruction groups (names follow WAM usage; the exact encoding is
an implementation choice, one word per instruction plus inline operands):

* **Head matching**: `GET_CONST w`, `GET_INT k`, `GET_NIL`,
  `GET_STRUCT fid arity` (followed by that many unify operands),
  `GET_LIST` (two unify operands follow). `UNIFY_VAR_FIRST off`
  (first-occurrence head variable: plain write, no occurs check),
  `UNIFY_VAR off`, `UNIFY_CONST w`, `UNIFY_INT k`, `UNIFY_NIL`,
  `UNIFY_STRUCT ...`, `UNIFY_LIST`. The compiler picks the occurs-check-free
  variants from the same analysis that already produces `PFirst`, and marks
  structure cells ground when it can prove groundness during construction.
* **Argument construction**: `PUT_VAR off`, `PUT_CONST w`, `PUT_INT k`,
  `PUT_NIL`, `PUT_STRUCT ...`, `PUT_LIST`, plus the existing compiled
  arithmetic plans (`PlanImm`/`PlanSlot`/`PlanSI`/`PlanIS`/`PlanSS` become
  `ARITH_*` instructions writing an operand slot) promoted from expressions
  to instructions.
* **Control**: `CALL key arity`, `EXECUTE key arity` (last call, tail
  position, reuses the activation), the cut barrier and if-then-else commit
  operations as they exist today, and clause entry through the per-clause
  entry-offset table described above.
* **Indexing**: per predicate, a decision tree over dereferenced argument
  tags with `SWITCH_TAG arg` jump tables (atom/int/struct/nil/list/bound-ref
  classes) and multi-argument refinement as today, resolving to candidate
  ordinals and stream offsets. Dedicated selection for `[]`/`[_|_]` clause
  pairs and for one-clause predicates, which SWI has and the Core lacks
  ([ENGINE-EXTERNAL](2026-10-18-ENGINE-EXTERNAL.md)).
* **Escape**: `ESCAPED n`, the boxed-goal side entry.

### What `ESCAPED` must mean for the interpreter

The plan above says the JIT declines any span containing `ESCAPED`; the
interpreter needs the complementary rule, and getting it wrong is what decides
whether the stream covers anything at all. A clause whose body contains a
single exotic goal - `once`, `if-then-else`, `not`, `findall`, a table call, a
dynamic fact, a leaf builtin - must **not** fall back to the tree wholesale,
or the stream would cover almost no real program. Instead:

* The head match is always encoded. An unencodable head pattern (only
  `PArith` today) is the one whole-clause fallback.
* The body is encoded up to the first goal outside the subset, and that point
  is `ESCAPED n`, whose side entry is **the remaining `[Goal]` list itself**.
  The VM then calls `runGoals` with the same base, barrier, depth and next
  continuation, exactly as the tree would have.
* Consequently `ESCAPED` needs no re-expression of `GOr`/`GIf`/`GNot`/
  `GFindAll`/`GMinimize`/`GTable`/`GAssert`, and their `Alt` and `Cont`
  constructors are untouched. It also means every clause streams its head
  match even when its body is entirely exotic.

Two instructions therefore carry an index into a per-clause side table of
boxed values rather than unboxed words: `CALL`/`EXECUTE` (the `PredRef` and
its `Maybe Trust`) and `ESCAPED` (the remaining goals). A third,
`GOAL n`, runs one whitelisted single goal whose successor is the stream
rather than a goal list; the initial whitelist is `GIs`, `GCmp` and `GCheck`,
which is what lets the arithmetic bodies of `loop`, `fib` and `range` stream
at all. `GOAL` is only sound for goals whose continuation is a single action,
so the encoder never emits it for a goal that can re-enter `runGoals` on a
goal list of its own.

### Load-time compilation

Compilation happens **once per program at load**, which closes the per-query
compilation cost identified in
[PER-CALL-COSTS](2026-10-20-PER-CALL-COSTS.md) (about 0.09 ms per query).
That is not a caching tweak, and it is not served by
[Cache.hs](../src/Infera/Compile/Cache.hs), which caches legacy `ClauseCode`
for the `Machine` path keyed by clause ordinal with source witnesses and has
no relationship to `CoreProgram`. Today
`compileProgram :: Store -> P.Program -> S.Query -> IO (Either Unsupported CoreProgram)`
interns atoms and functors into a **fresh per-query store** (`startCore`
calls `newSymbols` and `newStore`) and bakes the resulting words and ids into
`PStruct !Word'`, `Key`, `cpNil`, `cpCons` and `cpArith`. Three changes are
therefore prerequisites, and one of them is easy to miss:

1. The **intern tables** become program-scoped and append-only, shared by
   every query's store. That is not only `Symbols`: `constantWord` boxes
   every integer outside the 61-bit immediate range, every float and every
   string into a store-local `boxes :: IOArray Int Boxed`, and the resulting
   `BOX` index is baked into `PWord`. A shared plan whose `BOX` index meant
   one thing in the compiling store and something else in the next query's
   store is a silently wrong constant. The boxed table therefore moves into
   `Symbols` (and with it `rBOX`, which becomes a counter beside the table
   rather than a store register), which also makes `compileProgram` — and so
   `coreSupports` — independent of any live store.
2. `CoreProgram`, and with it the instruction stream, is memoized and shared
   across queries as an immutable unboxed array. `CoreProgram` currently
   carries the query's goals, so the memo holds the program half only
   (`cpPreds`, `cpNil`, `cpCons`, `cpArith`, and the program's own
   `cpUnsupported`) while the query half is compiled per query against it.
   The key cannot be a content digest: `P.Program` has none, and hashing
   `show program` would cost more than the compilation it saves. Key it on
   **program identity** instead - one entry holding
   `(StableName program, program, image)`, so a repeated query against the
   same loaded program hits, a reloaded or edited program misses, and
   retaining the `Program` in the entry is what stops a later allocation
   from reusing its address and forging a hit.
3. `coreSupports` answers from the memoized program image plus the compiled
   query goals, without building a machine
   ([Core.hs](../src/Infera/Core.hs) currently does
   `fst <$> runCore program query`, and `solveQuery` calls `runCore` again,
   so the fallback path compiles twice).

Runtime interning of builtin constants stays legal: it only adds ids no
compiled plan mentions. Because the tables are now shared across queries,
`internAtom`, `internFunctor` and `box` grow them under one lock; queries stay
interpreter-serialised, so this serialises only the cold interning path.

One case cannot be eliminated and is now decided: goals compiled at runtime
for `call/N` (`compileGoalTerm` with `ctxDynamic = True`) **keep the tree
path**. They are compiled to `Goal` values and run through `runDynamic`, which
already builds its own activation block; giving them a stream cache would
duplicate that machinery for a path that is not hot, and a `GOAL`/`ESCAPED`
boundary cannot be synthesised for a goal that does not exist at load time.

### Dispatch

The dispatch loop keeps the lessons of the earlier experiments: no shared
`where`-bound closures on hot paths, top-level local functions, strict
driver arguments where they cut allocation. The interpreter for the stream
is a tight `fetch/decode/dispatch` loop over the unboxed array.

**Prototype the loop before committing to the rewrite.** The recorded
lessons of this code base - "allocation is not CPU in GHC", unboxed frames
5-14% slower at equal allocation - make it plausible that a hand-written
dispatch loop over unboxed words is CPU-neutral or worse than case-of-case
over plan trees, where GHC's optimiser does the dispatch. Build the stream
for one predicate family (reverse and append) behind a flag, measure on
[core-major](../bench/core-major.hs), and only then convert the rest.

The prototype's instruction set is the head match (`GET_FIRST`, `GET_VAR`,
`GET_CONST`, `GET_STRUCT`, `GET_LIST_FIRST` and the nested `UNIFY_*` operands
they carry), argument construction (`PUT_*`, and `PUSH_*` for the children of
a nested structure, on the argument registers above the callee's arity, which
is what WAM uses the same registers for), `CALL`/`EXECUTE`/`PROCEED`,
`CUT`, `FAIL`, one `CHECK_BOUND` at each goal boundary (the per-goal
`reconciled` check `runGoals` performs, so a pending constraint binding is
still installed between goals), `GOAL` for `GIs`/`GCmp`/`GCheck`, and
`ESCAPED`. Arithmetic belongs in the prototype rather than the first
fragment extension, because whole-clause escape would otherwise leave
`loop`, `fib` and `range` entirely on the tree and the measurement would say
nothing about the two workloads this plan exists for.

Two call details have to be reproduced exactly, because they are what makes a
clause tail-recursive: `CALL` passes `frame = 0` and continues in a stream
continuation, while `EXECUTE` passes `frame = base` and continues in the
caller's continuation, so the encoder rewrites a trailing `CALL; PROCEED`
into `EXECUTE`. Clause selection itself is untouched: `candidateClauses` and
the `AltClauses` ordinal walk already are the decision structure and the
allocation-free filter that the `SWITCH_TAG` note asks for, so the prototype
adds no indexing machinery of its own and the `TRY`/`RETRY`/`TRUST` question
does not arise.

### Control state: the one new continuation

The real cost of this step is not the encoding, it is that a suspended clause
now has a fourth kind of control state. One constructor is added:

```
CStream stream pc base barrier depth next
```

and six places in [Run.hs](../src/Infera/Core/Run.hs) have to know about it -
`run'` (resume the loop), `contDepth` (the depth is in the frame),
`dropEmpty` (nothing to skip), `tailFrame`'s `dead` (same age rule as
`CGoals`: `other == base` is live, `other < base` is dead, otherwise walk on),
`checkInvariants`' `checkCont`, and the collector's `markCont` and `relocCont`.
The compiler's `-Wincomplete-patterns` finds them; the parity suite with
`--gc-limit 1` proves them.

**Collection is where the stream is simpler than the tree, and also where it
costs something.** The tree's continuations hold `[Goal]` and `Pattern`
values, so the collector must rewrite them: `Liveness.relocateGoals` turns
every slot reference into a `PWord` of the forwarded cell and sets the base to
0, which is why a detached plan can no longer use its frame. Code is
immutable `Int` words and cannot be rewritten, so a `CStream` instead

* marks **its whole activation block live**, from the `markerWord` cell at
  `base - 1` through `base + markerVars - 1`. Mark-compact preserves address
  order, so a fully live contiguous block stays contiguous and every operand
  offset in the code stays valid; and retaining the marker cell keeps the
  block's capacity word readable, which is what `tailFrame` would look at if
  the frame ever became reusable;
* relocates with a single `forward base` — one address instead of a rewritten
  goal tree.

The cost is that a suspended stream cannot drop the slots that the remainder
of its body no longer reads, so on a collection-heavy run a stream keeps up to
one clause activation per suspended frame more than the tree would. The
fragment's clauses have a handful of variables, and the alternative - a
per-`pc` live-slot map, which breaks contiguity and so breaks the operand
offsets - is worse. Record the residency difference in the Step 2 report
rather than discovering it later.

Abort criterion: if the stream interpreter is more than 5% slower than the
tree interpreter on the four standard workloads after tuning, stop. Step 3
does **not** strictly depend on Step 2 - Sol JITs from KIR, a tree IR, not a
flat array - so lowering from plans remains available, at the cost of more
Haskell-side codegen logic and no native indexing.

Acceptance: parity suite passes, including `--gc-limit 1`, in both modes
(`INFERA_CORE_STREAM=1` and `INFERA_CORE_STREAM=0`), because the flag is the
only thing that makes a divergence bisectable; reverse and fibonacci improve
or hold on [core-major](../bench/core-major.hs); clause-selection cost stays
allocation-free; per-query compilation cost is gone from a short-query
measurement; GHC allocation per inference is flat or lower in both modes, and
the residency delta the collector note predicts is measured, not assumed.

**As landed** ([WAM-STREAM](2026-10-30-WAM-STREAM.md)). The load-time half is
done and the instruction stream is a working prototype behind
`INFERA_CORE_STREAM`, with three findings that change what comes next:

* The fragment is head matching, argument construction, `CALL`/`EXECUTE`,
  cut, fail, unification and the per-goal boundary check. `GOAL` was written,
  measured and removed: `is` and comparisons are one `step'` branch in the tree,
  so an instruction fetch, a side-table load and a fresh continuation for them
  cost more than the dispatch they replace (`loop` and `fib`, the two
  arithmetic-heavy workloads, moved the wrong way by 10-30% with `GOAL` in).
  They stay on the tree until the dispatch is cheaper; that is fragment growth
  item 3, not slice 0. Admissibility therefore has a second condition beyond
  "encodable": a clause whose first real body goal is outside the fragment is
  left wholly on the tree, because otherwise it pays the dispatch and replaces
  nothing. That condition is what keeps `loop` at its previous cost, and it
  follows from the measured reason the tree wins there - the tree's per-goal
  work is *per term*, and a goal with no terms has none to remove.
* The collector treatment proposed above is what makes the stream viable with
  `--gc-limit 1`: a suspended stream marks its whole activation block live, so
  the block stays contiguous through compaction and relocation is one forwarded
  address. The predicted residency cost did not appear on the four standard
  workloads.
* The acceptance item that is **not** met is allocation on the tree path: with
  the interpreter compiled into the driver module, per-query allocation rises
  by 19-37% even with the flag off and no stream compiled at all, and removing
  only the interpreter's code from the module restores the baseline exactly.
  It is not executed work and it tracks whether `run'`'s stream arm performs a
  real call rather than raising; it survives `-O2`, extra simplifier
  iterations, forced `INLINE` pragmas and a `NOINLINE` dispatch wrapper, and
  moving the interpreter into its own module behind a record of driver
  primitives cost the stream 30% of its speed and was reverted. Finding the
  lost optimisation - or accepting a library `-O2` profile - is the first
  thing to do before the stream becomes the only interpreter; the tree is
  still the specification and CI runs the parity corpus on it.



## Step 3 - the native JIT of deterministic predicates

The Sol tier's structure maps directly. Its load-bearing ideas, restated for
this engine:

* **Admissibility is a pure predicate over plans** (`jitOK` in
  `fprisc:compiler/Sol/JitCore.hs`), checked once at load. Refusal is normal
  and silent (printed under `INFERA_JIT_DEBUG=1`); the interpreter remains
  the specification, native code is an accelerator.
* **Per-callsite specialization with a cache key** of argument types. Sol
  infers JI/JD/JW itself; Infera already computes sorts and modes per
  predicate ([CONTRACTS-PERFORMANCE](2026-10-17-CONTRACTS-PERFORMANCE.md)),
  so the key is `(PredKey, [Sort], [Mode])` with no new inference pass.
* **Budgets reified into the native code**, reconciled around the call by
  the Haskell driver (the `fuel*` pointer handed to every Sol driver, as in
  `fprisc:compiler/Sol/VM.hs`). See [Budgets](#budgets-two-counters-not-one)
  - Infera's resolution-depth cap is a semantic counter and must not share a
  cell with an allocation bound.
* **Bit-identical by construction**: same tag arithmetic, `quot` division,
  same trail discipline, same evaluation order. The verification story below
  is belt on top of these braces.

The tier is **off by default** until the verification gates below are green
in CI on both hosts, then on, with `INFERA_JIT=0` as the permanent escape
hatch (Sol's `SOL_JIT=0` precedent).

### The initial fragment

* Deterministic: declared or inferred `det`/`semidet`. Determinism is what
  makes a native call clean - success proceeds, failure fails the calling
  clause, and no retry state exists. Inferred semidet commits qualify when
  the switch argument is ground at call time, the same condition the Core
  applies today.
* All argument modes known; `+`/`ground` integer arguments are unboxed
  `i64` parameters, other arguments are cell addresses.
* Body in the pure fragment: `is` and comparisons over `INT`, ground-mode
  unification, tail self-call (compiled to a native loop). No cut, CLP,
  tabling, dynamic facts, escape instructions or IO inside the span.
* Single clause, or selection reducible to a native jump table over clause
  entry offsets.
* Everything else - bignums, floats, unexpected tags, constraint-sensitive
  variables - declines.
* **Errors are part of the fragment definition, not an afterthought.** A
  span that can raise an instantiation or sort error, a determinism error,
  division by zero, or an `i64` overflow into a bignum must either be
  excluded or be able to leave through the bailout exit below. Pre-flight
  magnitude proofs are an alternative for arithmetic (`|a|,|b| < 2^31` makes
  `a*b` overflow-free) but they are fragile; bailout is the general answer.

The first slice is the tail-loop fragment: counting loops, factorial,
`length`-style reductions. These allocate nothing and bind nothing inside
the span, so the native loop never needs the collector and an early exit
leaves no store state to reconcile. Be clear about what this proves: loop
90,000 is the Core's **best** relative result (~1.0x Scryer), so slice 1 is
a proof of the plumbing - emitter, shim, dynamic import, budgets, xcheck -
and its gate is "loop improves and parity holds", not "the gap closes".
Reverse, at ~2.5x Scryer and ~9.3x SWI, allocates a cons cell per iteration
and needs structure arguments, which is fragment-growth item 2. That is
where the stated motivation is actually addressed, and the Step 0 coverage
measurement decides whether it is worth reaching.

### Calling convention

```
i64 pred(Store *s, i64 *args, i64 *budgets)
  ; returns 1 = success, 0 = failure, 2 = declined (pre-flight only),
  ;         3 = depth exhausted, 4 = bailed out, 5 = error pending
```

`args` holds the argument words (addresses of argument cells, per WAM
calling convention); `budgets` points at the depth and allocation cells the
driver reconciles after the call. The store's base pointers (`cells`,
`trail`, `regs`) are read from `s` at entry and never cached across a
return. Small fixed assembler routines implement `deref`, `bind +
trail-if-older-than-HB`, and tag tests, emitted once per unit like Sol's
KIR helper functions; the predicate body lowers from the Step 2
instructions of its clause.

Exits other than success and failure are all handled by the Haskell driver,
never by native code:

* **Decline (2) is a pre-flight check only**: operand tags and entry
  capacities are scanned before any trail write, so a declined call reruns
  on the interpreter with no double-trailing.
* **Bailout (4) is the mid-span exit.** Overflow, an unexpected tag met
  after binding began, or a construct the emitter turns out not to cover
  returns 4. The driver then unwinds to the entry marks it captured before
  the call - `unwindTrail` to the entry trail mark, `setHeapTop` to the
  entry heap mark (which also prunes `logicalIds` above it), and truncation
  of the bound log - and reruns the call on the interpreter. This is exactly
  what the interpreter's own failure path already does, so it is proven
  machinery. Requiring `rCLP == 0` at entry, or a proven bound-log
  truncation, keeps constraint reconciliation out of the question. Without
  this exit the fragment would have to prove the absence of every runtime
  error before the first trail write.
* **Depth exhausted (3)** reproduces the interpreter's
  `depth > maxResolutionDepth` path, which is `raiseItems [BranchExhausted]
  (backtrack m)`: an item in the answer stream, not an exception. The driver
  emits it from the native return, at the iteration count the native loop
  reports.
* **Error pending (5)** names a `SolveError` the driver raises identically
  to the interpreter path, with the same predicate key and source position.

### Entry conditions the driver must establish

The depth budget bounds iteration count; it does not bound memory. Two
arrays can grow in the middle of a call and neither can grow from native
code: the trail (`pushTrail` reallocates by doubling) and the bound log
(`recordBound`). The heap block does not grow at all under Step 1's
reserve-once variant, but `rCAP` is still a hard bound the span must
respect. Before each native call the driver checks, and declines rather than
risk overrunning:

* `rH + maxAlloc <= rCAP` for the span's static allocation bound;
* `rTR + maxBindings` within the trail's capacity, growing it in Haskell
  first if needed;
* bound-log capacity for `maxBindings` when `rCLP /= 0`, or `rCLP == 0`;
* the boxed table cannot be needed (no `BOX` word is constructible in the
  fragment);
* heap, trail and bound-log base addresses are read from the store and
  passed in `s`, never carried over from a previous call.

A native span must also never span a collection: collection runs at call
boundaries in the interpreter, and the leaf-per-call rule keeps it that way.

### Store invariants native code must maintain

Each of these is a silent-divergence source rather than a crash, so they are
listed explicitly and the cross-check replay compares them:

* the **ground memo** on constructed structures, including the in-place
  update path that `trailValueIf` trails when an existing structure becomes
  ground later. Omitting it makes `funGround` answers diverge, which then
  changes occurs-check elision and inferred-semidet commit decisions
  elsewhere in the engine;
* `rH` after any allocation, and `markerWord` blocks for any frame that tail
  reuse may read through `markerVars`;
* the trail entry encoding: an even entry `2*addr` resets a cell to unbound,
  an odd entry `2*addr+1` restores the word pushed just below it;
* `rBOUND` recording on every binding while `rCLP /= 0`;
* the occurs check on any variable-to-structure binding whose target is not
  a proven-fresh first-occurrence slot and whose value is not proven ground;
* never touching `rHB`, `rIDENT` or `logicalIds`, which belong to the
  interpreter's choice and naming paths.

### Budgets: two counters, not one

`maxResolutionDepth` is 100,000 and exceeding it puts `BranchExhausted` in
the answer stream, so the depth count is user-visible semantics, not a hint
([PER-CALL-COSTS](2026-10-20-PER-CALL-COSTS.md) lists lifting this cap as
separate remaining work). The tail-loop fragment is precisely the case that
reaches it: loop 90,000 is 90% of the way to the cap. Two cells are
therefore handed to native code:

* `depth`, ticked once per resolution exactly as the interpreter ticks it,
  including tail calls, so that `loop 100001` and `loop 200000` report
  exhaustion at the same point with the tier on and off;
* `allocBudget`, a safety bound on cells and trail entries the span may
  consume, which exists only to guarantee the span returns.

Charging allocation to the depth cell, as a single-fuel design would, breaks
the exact-depth semantics. Acceptance includes both loop cases above, run
with the tier on and off, compared item for item.

### Foreign calls

`foreign import ccall unsafe "dynamic"`, following the `mkDrv*` pattern in
`fprisc:compiler/Sol/HandJIT.hs`. The `unsafe` choice is what makes the call
nanoseconds rather than tens of nanoseconds, and it carries two obligations
the fragment already satisfies: native code must not call back into Haskell
and must not block. Because the span touches only pinned off-heap storage,
it is GC-safe by construction. The executable is built
`-threaded "-with-rtsopts=-N"`, so an unsafe call does not release the
capability; that is acceptable for a bounded leaf span and is another reason
the allocation budget exists.

### Reuse from fprisc

What lifts: the C shim's shape (after the `MAP_JIT` work below), the
instruction-encoder and label-fixup skeleton of `AsmA64.hs` and
`AsmX64.hs`, the `mkDrv*` dynamic-import plumbing, and the case-file
cross-check dump format. What does not lift is the lowering. Sol's
assemblers are small (146 and 176 lines) and implement a **stack machine**
for KIR: `push`/`pop` on `sp`, frame slots addressed through `slotAddr`
bounded to 255 slots and `imm12` offsets, `FuelTick`, `Trap`, and one `sdiv`
with a poison path. An Infera span wants a register convention (cells base,
H, TR, HB, argument cells, the two budget cells), indexed
`ldr x, [xBase, xIdx, lsl #3]` addressing for a heap of a million cells or
more, tag tests, `deref` loops, bind-and-trail-if-older, `quot`/`rem`
semantics and overflow checks. Budget a new emitter per host seeded by Sol's
encoders; treat the 322 lines as a starting library, not as the tier.

The KIR lowering structure (`fprisc:compiler/Sol/KIR.hs`) is still the model
for the instruction-to-machine-code lowering. Host support: aarch64 and
x86-64 (SSE4.1 for `roundsd`) as in Sol, selected at startup by
`System.Info.arch`, absent otherwise with the tier disabled.

### Verification

The standard parity group is weaker than it looks for this purpose: since
`1f075ac` answers are compared up to renaming (`alphaText` in
[core-engine.hs](../bench/core-engine.hs)), and
[CONTROL-STACKS](2026-10-19-CONTROL-STACKS.md) records a findall bug that
exact-id parity had hidden. Item-sequence parity will not catch a native
span that produces a wrong-but-isomorphic answer, nor ground-memo divergence
that does not change answers. Gates, in order:

1. The `core-engine` parity group with the tier forced on and off, including
   `--gc-limit 1`, over `test/core/*.nprolog` and the examples.
2. `loop 100001` and `loop 200000` item-for-item, tier on and off, for the
   depth semantics.
3. `INFERA_CORE_TRACE=1` stream comparison, tier on and off.
4. Cross-check dumps in the Sol style: `INFERA_JIT_XCHECK=<dir>` writes a
   case file per native call (predicate, input words, output words, both
   budget cells, exit code); a replay tool reruns the same call on the
   interpreter and compares **store words**, not exported terms, so the
   ground memo and trail encoding are covered.
5. A hedgehog differential generator over small programs comparing native
   execution with `INFERA_JIT=0`, following the generated-parity idiom
   already in `CorrectnessTest` and `InferenceTest`.
6. Gates 1-5 run in CI on **both** hosts: the matrix already has
   `ubuntu-latest` (x86-64) and `macos-26` (arm64), but CI currently runs
   only `cabal test all` and `test/cli.py`, so a `core-engine parity` leg is
   added rather than assumed.
7. `INFERA_JIT=0` disables the tier so any behavioral suspicion can be
   bisected to the native span.

## Fragment growth (after the first slice, in expected-value order)

1. **Structure arguments with the ground memo**: ground `STR` words passed
   unboxed by address, with the occurs check elided where the compiler
   proves freshness - the reverse/append shape. This is the fragment that
   addresses the workload this plan was written for, and the Step 0 coverage
   measurement is what ranks it against the items below.
2. Deterministic multi-clause predicates: indexing as a native jump table,
   with fail-fast to the interpreter's choice machinery only outside the
   compiled clause set.
3. `semidet` bodies ending in a comparison (the membership-test shape).
4. Non-recursive det bodies inlined at their call sites (Sol's closure
   inlining, `satJoins`).

Each extension is its own admissibility widening, its own parity run, and
its own dated report.

## Risks

* **Executable memory on Apple Silicon is unbudgeted, not solved.** The
  `fprisc` shim this plan intended to reuse
  (`fprisc:compiler/cbits/handjit.c`) is `mmap(PROT_READ|PROT_WRITE)`,
  `memcpy`, `mprotect(PROT_READ|PROT_EXEC)`, `__builtin___clear_cache`; it
  contains no `MAP_JIT` and no `pthread_jit_write_protect_np`, and neither
  appears anywhere in that repository. macOS arm64 enforces W^X: anonymous
  memory must be mapped `MAP_JIT` to become executable, and writes require a
  **per-thread** `pthread_jit_write_protect_np(false/true)` toggle around
  emission. Consistent with this, `fprisc`'s own records validate the A64
  path under `qemu-aarch64` on Linux
  (`fprisc:docs/2026-09-02-JIT.md`) and measure macOS arm64 with the JIT
  disabled (`fprisc:docs/2026-09-29-Sol-Improvements-Needed.md`). Budget
  roughly fifty lines of C for an `infera_jit_alloc` with an
  `#if defined(__APPLE__) && defined(__aarch64__)` branch, and prove it in
  Step 0 before anything else in Step 3. If Infera is ever shipped as a
  hardened or notarized binary it also needs the
  `com.apple.security.cs.allow-jit` entitlement; Homebrew's
  build-from-source binary is ad-hoc signed, so it does not today. Linux
  x86-64 with an `execmem`-denying policy is the analogous, rarer case.
* **Depth semantics**: the cap is a semantic bound that surfaces as
  `BranchExhausted` in the answer stream, so the native loop must tick it
  exactly and exit through the driver at the same iteration the interpreter
  would. Two budget cells, and the `loop 100001`/`loop 200000` gate, are
  what keep this honest.
* **Mid-span exit correctness** rests on bailout unwinding to the entry
  marks in the driver, never in native code, and on decline staying
  pre-flight. A decline after trailing without that unwind would corrupt the
  trail. The admissibility checker, the entry-condition checks and the
  cross-check replay all enforce it.
* **Capacity overrun** is the failure mode that does not announce itself:
  native code cannot grow the trail or the bound log and cannot exceed the
  reservation. The entry conditions above are mandatory, not an
  optimisation.
* **GHC calling overhead**: an `unsafe` dynamic-import `ccall` per native
  predicate call is nanoseconds - fine at call granularity, and the fragment
  bans per-inference foreign calls. A `safe` call would cost tens of
  nanoseconds and erase much of the win.
* **Growth invalidation**: a native span must never span heap growth,
  compaction or collection; the leaf-per-call rule, the entry capacity
  checks and Step 1's pinned blocks keep this invariant by construction, with
  the caveat that Step 1 kept growth-by-copy and so a base read at span entry
  is valid only for that span.
* **Step 2 may not pay for itself.** A hand-written dispatch loop can be
  slower than GHC's case-of-case over plan trees; the prototype and its
  abort criterion exist for that reason, and Step 3 does not strictly depend
  on Step 2.
* **Shared intern tables widen the blast radius of a wrong constant.** With
  `Symbols` and the boxed table program-scoped, a `BOX` index or functor id
  baked at load time is now read by every later query against that program.
  The tables must therefore be append-only and locked, and any future change
  that *retires* an id (interning "cons" differently, compacting the boxed
  table) is a correctness bug rather than an optimisation.
* **Two engines, one semantics.** The stream interpreter and `step'` coexist
  until the tree path is retired, so every change to binding, trailing, the
  ground memo or the occurs check has to be made twice or made in the shared
  store primitives. Keeping the instructions thin wrappers over
  `unify`/`bind`/`structureWord`/`slotWord` rather than re-deriving their
  behaviour is what keeps the two paths from drifting; the parity suite in
  both modes is what catches it when they do.

## Sequencing

Step 0 (coverage measurement, macOS arm64 executable memory) runs first and
can reorder everything below. Step 1 (store) is independent and lands next.
Step 2 (instruction stream) is the bulk of the work: it is prototyped on one
predicate family against an explicit abort criterion before the driver's
control state is converted, and its load-time compilation prerequisite
(program-scoped intern tables, memoized program image, a cheaper
`coreSupports`) is part of it rather than a follow-up - it is independently
valuable, it is the part with no semantic risk, and it can land while the
stream is still behind its flag. Step 3's first slice is small once Steps 1-2
exist, but its lift is the emitter and the shim, not the reused assembler;
the Step 0 coverage number decides how far past the first slice the fragment
grows. Steps land on branches with the standard acceptance gates: full suite,
parity group including `--gc-limit 1`,
[core-major](../bench/core-major.hs) and
[core-engine](../bench/core-engine.hs) medians, GHC allocation per
inference, and a dated report per landing.

The intended order inside Step 2, once the prototype's number is in:

1. Head matching, argument construction, `CALL`/`EXECUTE`, `CUT`, `FAIL`,
   `PROCEED`, `ESCAPED` - the prototype, behind `INFERA_CORE_STREAM`.
2. `GOAL` for the single-goal builtins (`GIs`, `GCmp`, `GCheck`, then
   `GEquiv`/`GNeq` ground path, `GWrite`/`GNl`).
3. `GOr`/`GIf`/`GOnce`/`GNot` as instructions, so the control constructs that
   dominate ordinary Prolog bodies stop escaping. Each needs its own `Alt`
   variant pointing at a stream, which is the same `base`-age rule as
   `AltGoals`.
4. Only then consider the indexing work, which changes selection rather than
   execution and is where the remaining `SWITCH_TAG` note belongs.

Step 3, Track 2, and Track 3 are implemented across:

- `cbits/infera_jit.c`: `infera_jit_alloc`, `infera_jit_free`, and `infera_jit_has_sse41` using `MAP_JIT` + `pthread_jit_write_protect_np` + `sys_icache_invalidate` on macOS arm64.

- `src/Infera/Core/Jit.hs`: Load-time admissibility analysis (`compileJitKernel`) and FFI invocation/reconciliation (`invokeJitKernel`) covering:
  - **Slice 1 (`matchCountdownLoop`)**: Countdown/arithmetic integer tail loops (`loop/1`).

- `src/Infera/Core/Run.hs` (Track 3):
  - **Guard-pruned first-argument integer indexing (`pruneCandidates` / `clauseAcceptsInt0`)**: Prunes variable-head clauses whose leading `GCmp` guard rejects the concrete integer first argument (reducing `fib 0 F` and `fib 1 F` from `Candidates [0, 2]` / `[1, 2]` to `OneCandidate 0` / `OneCandidate 1` and eliminating 121,393 dead choice points, 242,786 `saveArgs` cells, and 121,393 `CReturn` frames in `core-fib`).
  - **First-occurrence `GIs` fast path (`PFirst i`)**: Writes immediate integer results directly to `cells[base + i]` without `numericTarget`, `unify`, `deref`, or trail checks.
