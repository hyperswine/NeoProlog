CLP(Z)

Integer constraints over interval domains with bounds propagation. Enough for puzzles, scheduling toys and N-queens; residual domains and constraints are shown in answers.

Goals #

GoalMeaning
X in Lo..Hirestrict X to an interval; inf and sup give open bounds; a list on the left restricts every element
A #= Binteger equality of expressions
A #!= Bdisequality
A #< B, A #> B, A #<= B, A #>= Bordering
all_different Xsdistinct integer values, with global finite-domain propagation (all_distinct is a synonym)
reify (A #<= B) TruthTruth is 0 or 1, equivalent to the relation; supports all six CLP comparisons in both directions
label Xsenumerate the variables' finite domains, smallest domain first (labeling is a synonym)
labeling [min Cost] Xsreturn one minimum using branch-and-bound; finite integer domains, with an integer cost ground at each complete assignment
minimize Cost Goalscan a finite search while retaining only the first least-cost answer and its bindings/output; no branch pruning; every answer must have a ground integer cost

Both optimisation forms return one optimum, fail if there are no solutions, and do not claim an optimum if any branch errors or the search is incomplete. Only [min Cost] is supported by two-argument labeling. Pruning can change the first tied assignment encountered. The breadboard example constrains its score before labeling [min Cost], allowing incumbent bounds to prune partial placements.

Expressions may use + - * and integer literals; * of two unknowns, /, % and ^ stay residual until they become linear or ground.

D #= abs Expr propagates bounds when D and Expr are linear expressions. Once the sign is known, it becomes a linear equality. Otherwise the absolute-value relation remains residual. Reification and absolute values let objective costs constrain a model before labeling.

Examples #

> X #= 3 + 4?
X = 7
> X #> 3, X #< 6?
X in 4..5
> X in 0..5, Y in 0..5, X + Y #= 10?
X = 5, Y = 5
> X + Y #= 10?
X + Y #= 10
> [X, Y] in 0..20, X + Y #= 10, X - Y #= 2, label [X, Y]?
X = 6, Y = 4
send_more_money [S, E, N, D, M, O, R, Y] <-
  Vars = [S, E, N, D, M, O, R, Y],
  Vars in 0..9,
  all_different Vars,
  S #!= 0, M #!= 0,
  1000 * S + 100 * E + 10 * N + D + 1000 * M + 100 * O + 10 * R + E
    #= 10000 * M + 1000 * O + 100 * N + 10 * E + Y,
  label Vars.

> send_more_money L?
L = [9, 5, 6, 7, 1, 0, 8, 2]

How propagation works #

  • Domains are intervals with a set of excluded values. Unifying a constrained variable with an integer checks the domain; with another variable, the domains are intersected; with anything else it is a type error.
  • Changed variables wake only their dependent constraints. List domains are posted together before propagation. Linear constraints Σ cᵢxᵢ + k ⋈ 0 use aggregate bounds, with linear coefficient visits per pass. A constraint over a single variable is absorbed into its domain; a domain that shrinks to one value binds the variable. An equality between two variables with unit coefficients (Y #= X + 2, Y #= 7 - X) is domain-consistent: holes removed from either side are removed from the other, so auxiliary variables such as queens' diagonals prune as well as direct disequalities. Larger sums keep bounds propagation.
  • Global all_different excludes fixed values and uses bounded Hall-interval and matching checks for finite domains. These checks detect impossible groups and remove unsupported values; larger domains retain cheaper propagation.
  • #!= with one unknown punches a hole in its domain; with several it waits.
  • Labeling picks the unbound variable with the smallest finite domain and tries its values in order, propagating after each. Labeling a variable with an unbounded domain is an error.

The general disequality A != B is also a delayed constraint (it is checked whenever its variables get bound) and appears in answers as X != 1.
