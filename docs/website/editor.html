Editor support

The repository ships a VS Code extension with a language server for .nprolog and .infera files.

Install the extension #

cd lsp
npm install
npm run install-extension     # packages infera-lsp.vsix and installs it into VS Code

Or run npm run package and install the .vsix through Extensions → … → Install from VSIX.

Features #

  • Highlighting: a TextMate grammar plus semantic tokens for clause heads, declarations, sorts, modes, module namespaces and inline queries.
  • Hover: built-in documentation, predicate clause counts and declared signatures, declaration keywords, imported modules. CLP operators such as #=, #!= and #<= explain integer constraints and propagation with examples; hover anywhere on the operator.
  • Navigation: go to definition, find references and document symbols (name/arity), including mod:pred calls resolved through neoprolog.conf.
  • Completion: local predicates, module aliases (mod: completes the module's predicates), built-ins, and determinism words, flags, sorts and modes inside a declaration.
  • Diagnostics come exclusively from the compiler: undefined calls, arities, declaration and literal-sort conflicts, singleton warnings, parser and import errors. The editor checks live buffers on open, after a short edit debounce, and on save using infera check --json --stdin. Edits schedule only the changed buffer and its transitive importers. Unchanged source, dependencies and module mappings reuse cached diagnostics, including on duplicate saves and watcher notifications. Only relevant unsaved imports are sent to the compiler; imported errors link to their owning files, and outdated checks are cancelled. Changing performance-hint visibility filters cached diagnostics without rerunning the compiler.
  • Unsaved files: untitled buffers use the workspace as their import context. A missing or incompatible compiler produces an availability warning; highlighting and navigation remain available without a separate validator.

Settings #

SettingDefaultMeaning
infera.executableinferabinary used for infera check --json
infera.checkOnSavetruerun the compiler check on save
infera.checkOnChangetruerun the compiler check after unsaved edits

Opening a document checks it when either setting is enabled. Disable both to turn off diagnostics while retaining other editor features.

Other editors #

The server in lsp/server/server.js speaks standard LSP over stdio-less IPC as launched by the VS Code client; any editor that can launch a Node language server can use it by running node lsp/server/server.js --stdio after switching the connection to stdio, and the analyser in lsp/server/analysis.js is a plain module usable from other tooling.
